# Активация JOKER VPN — подготовка к подключению сервера

Реализованы серверный учёт срока, одноразовые ключи и экран Android «Подписка».
**Это ещё не система платного VPN-доступа:** данный сервис не выдаёт и не отзывает
VLESS/REALITY или Hysteria2-конфигурации. Существующий VPN не ограничивается этим
экраном. До продажи ключей необходимо интегрировать индивидуальные VPN-учётные
данные и серверное прекращение доступа после истечения срока, затем проверить
это на реальном узле. Одна только блокировка кнопки Android не защищает доступ.

## Правила

- Ключ содержит 192 случайных бита, выдаётся локальной командой администратора.
- При первой активации он закрепляется за секретным идентификатором установки.
- Срок увеличивается от `max(серверное время, текущий срок)`.
- Повтор с тем же ключом и идентификатором не добавляет дни снова.
- Другой идентификатор получает отказ. Копия данных приложения переносит тот же
  идентификатор; аппаратной привязки, аккаунтов и ограничения устройств здесь нет.
- В SQLite хранятся SHA-256 ключей/идентификаторов, без открытых секретов.
- Неиспользованный ключ по умолчанию истекает через 90 дней. Длительность тарифа
  выбирается при выдаче (1–365 дней), цены и оплата не задаются.
- Потеря данных приложения означает потерю идентификатора. Автоматического
  восстановления пока нет; не выпускайте сервис публично без процедуры восстановления.
- Android показывает дни по серверному ответу на момент проверки. При сетевой
  ошибке не показывает старые дни как актуальные. Дата телефона не используется.

## Проверка локально

```sh
python3 -m unittest discover -s activation -v
python3 activation/server.py --database /tmp/joker-test/ledger.sqlite3 issue --days 30
python3 activation/server.py --database /tmp/joker-test/ledger.sqlite3 serve
```

Сервер слушает только `127.0.0.1:8088`. Административного HTTP API нет.
Ключ из команды `issue` показывается только один раз; не отправляйте его в журналы.
Выданные реальные ключи и база не должны попадать в Git или публичные артефакты.

## Развёртывание (ещё не выполнено)

Нужны доступ администратора к узлу, HTTPS-домен с доверенным сертификатом и
разрешение хостинга на планируемый VPN-сервис. Рабочий Xray занимает TCP/443:
не заменяйте его слушатель. API размещается на отдельном узле/адресе либо отдельном
доверенном HTTPS-порту. Правила хостинга проверяются отдельно перед запуском продаж.

1. Создать системного пользователя `joker-activation` без shell, каталог
   `/opt/joker-activation` с `server.py`, принадлежащим root и недоступным для записи
   пользователю сервиса. Python 3.10+; сторонних зависимостей нет.
2. Установить `joker-activation.service` в systemd и запустить сервис.
3. Поставить перед localhost API TLS reverse proxy: лимит тела 1 КБ, таймаут
   запроса 10 секунд, лимиты соединений и запросов по реальному IP клиента
   (например, 2 запроса/сек, burst 10, не более 5 соединений/IP). Не доверять
   произвольному `X-Forwarded-For`. Не журналировать Authorization и тела запросов.
4. Закрыть внешний доступ к 8088. HTTPS-прокси должен передавать Authorization.
   Не отключать проверку сертификата на Android.
5. Сделать защищённую резервную копию SQLite через SQLite backup API; проверить
   восстановление. База является источником истины, потеря базы теряет подписки.
6. Задать переменную GitHub Actions `JOKER_ACTIVATION_URL`, например адрес
   `https://YOUR-ACTUAL-API-HOST:8444` (без пути, query и завершающего слеша).
   До этого экран честно сообщает, что сервис не подключён, и не принимает ключи.
7. Собрать подписанный APK из этой ветки, установить поверх `com.joker.vpn.app`.
   Проверить активацию, перезапуск приложения, повтор ключа, истечение срока,
   сетевую ошибку, Wi-Fi и Yota. Не использовать Preview для переноса платных прав.

Выдача ключа на сервере:

```sh
sudo -u joker-activation python3 /opt/joker-activation/server.py issue --days 30
```

## Контракт API

`POST /v1/status` с телом `{}` или `POST /v1/redeem` с `{"key":"JOKER-…"}`.
Оба требуют `Authorization: Bearer <64 lowercase hex characters>`.
Клиент генерирует 32 случайных байта и сохраняет их до первого запроса.
Ключ/идентификатор никогда не передаются в URL. Ответы имеют `Cache-Control: no-store`.

Успех: `status` (`inactive`, `active`, `expired`), `remaining_days`, `server_time`,
`expires_at` (Unix seconds). Ошибки: `invalid_key`, `used_key`, `expired_key`,
`invalid_token`, `invalid_request`, `temporarily_unavailable`. Ошибка сети после
запроса активации требует повтора с тем же идентификатором и ключом.

## Not run

- Развёртывание и HTTPS-проверка: действующий API-домен и доступ к серверу не предоставлены.
- Выдача/отзыв VPN-доступа: интеграция с рабочим узлом отсутствует.
- Проверки Android на устройстве: активация, повтор после потери ответа, закрытие/
  открытие экрана и приложения, touch/keyboard/D-pad, TalkBack, IME и прокрутка.
  У ассистента нет подключения к телефону пользователя или Android-эмулятору.
